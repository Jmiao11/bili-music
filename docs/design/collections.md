# 多 BV 合集设计（C1 / C2）

## 存储与快照

收藏与歌单使用 video / collection 条目，稳定 entryId 标识引用；去重分别按 video:<BV>、collection:<id>。同一视频单独收藏与合集内出现互不影响。合集引用各自保存 id、成员锚点 BV、标题、封面、视频数、加入时间、完整成员快照及 fetchedAt，不建立独立快照文件。

favorites.json、playlists.json 和 playback-state.json 分别按需升级：存在合集才写 v2，否则保持各自原 v1 格式；共用 VERSION 不变。第一次写 v2 前，在同一存储锁内保留原 v1 为同目录 `.v1.bak.json`，有效备份不覆盖，失败则停止写入。继续使用 tmp/bak/rename 原子写入。导入支持 v1/v2，完整预检后写入，失败整体回滚；ZIP 不导出保护备份。旧版不能读取新库或恢复 v2 播放状态，升级前建议导出备份。

## 刷新与失效

打开合集或开始一次合集父条目播放时显式刷新，同 id 并发请求合并。只有完整且 id 匹配的结果才能替换仍存活的 entryId 引用，其他结果保持快照与日期。网络/风控失败、成员删除、详情无旧合集或 id 不同均不足以证明合集整体删除，显示「来源无法校验」；只有已有确证状态才显示「合集来源已失效」。两者均允许尝试快照成员。不轮询全库、不自动换成员探测。详情请求使用独立无 cookie、8 秒客户端，风控不重试。

## 唯一队列与播放规则

资料库单击合集播放整体，双击取消延迟单击并展开；角标只展开。从展开视图播放仍是普通 BV 列表。收藏和歌单整体队列包含视频与合集父条目，父条目用 entryId 高亮；合集内部保存本次冻结成员列表、游标和剩余成员，视图刷新不中途重排播放。

随机模式先抽顶层条目，再按「合集内顺序」选择成员，最后使用原多P选择逻辑；禁用分P继续生效。N 按实际播放的音频单元计数，成员分P与外层共用名额；真实失败占名额，手动切走、取消、迟到结果不占。已听历史回放不重复扣除同一音频名额。顺序模式连播成员及其分P。上一首身份为 entryId + BV + CID，必要时保留历史成员元数据，即使后续刷新移除了成员也能返回实际听过的音频。

播放状态 v2 保存冻结队列、合集游标/配额、顶层与分P随机轮次、实际历史及进度；恢复不重新拉取并重排。请求版本与取消保护沿用现有机制，连续五个真实失败音频单元刹车。播放栏、播放历史、迷你窗、Media Session 均显示实际 BV 与分P。

## 取流边界与验证

C2 只调整调用侧选择哪个 BV / CID；Rust prepare_audio、解析器、本地代理、游客身份与 yt-dlp 不变。进一步修改取流须先确认。根同步挂载、根订阅最先、G0 193/140 与组件 props/回调边界保持。

持久化和状态机按严格模式验收：双 Node、CRLF、全部保留 canary、Rust fmt/build/test、冻结 fixture 与真实 DOM 回归，定向变异检查配额叠加和取消计数；分支双平台 CI 后由 Windows 完整手测及 Mac 播放冒烟确认。

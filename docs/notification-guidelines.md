# 用户操作反馈规范

所有贡献者添加用户反馈时应遵循本规范。提醒解释操作结果，不改变播放队列、循环、随机、分P或取流规则。

## 类型选择

| 类型 | 使用场景 | 展示方式 |
| --- | --- | --- |
| 轻提示 | 队列边界、空队列、重复操作 | 2 秒后消失，不抢焦点 |
| 成功反馈 | 主动操作完成且界面变化不足以说明结果 | 简短轻提示；播放/暂停不重复提示 |
| 处理中 | 搜索、解析、导入等异步操作 | 操作区域加载态，结束后移除 |
| 警告或可恢复错误 | 失败、部分成功 | 相关区域展示原因及重试等下一步；需要处理时持续显示 |
| 阻断错误 | 功能无法继续 | 错误状态页或浮层，提供恢复入口 |
| 确认 | 删除等需要用户决策的操作 | 执行前使用项目自定义确认浮层 |

禁止将普通结果做成确认框，禁止使用浏览器 alert/confirm/prompt。错误码和堆栈留在日志中；面向用户说明发生了什么，必要时说明如何继续。

## 当前统一入口

主窗口脚本通过 `showPlaybackNotice(message, { kind: "info" })` 发送轻提示或必要的成功反馈。入口位于 `ui/main.js`，复用已有 `#playback-notice`，不新建第二套 toast。

已有播放失败调用保持默认 `kind: "error"`，短提示保持 3200 毫秒；`persistent: true` 持续至播放流程显式清除。`clearPlaybackNotice()` 清除内容、定时器并同步窗口。当前 API 仅支持 info/error，其他类型使用上表规定的区域组件，不杜撰新 kind。

同时只显示一条消息，相同轻提示重复触发刷新期限，不排队。错误显示期间忽略轻提示；轻提示不得覆盖错误，也不得写入或清除业务状态条。普通消息使用 `role="status"`、`aria-live="polite"`，不抢焦点、不发声，不只靠颜色传达含义。

主窗口在现有播放提示位置显示，沉浸页复用现有顶部位置。`bilibili-music-notice-change` 通知 mini host 发布状态，`mini-player-state.notice` 将内容同步到 mini 标题区域的紧凑提示，保留控制按钮可操作。计时和优先级仅由主窗口管理，mini 不重复计时；新打开的 mini 接收仍有效的消息，已过期的消息不回放。

全局快捷键、系统媒体控制、沉浸页、mini 均复用主窗口切歌入口。主窗口隐藏时 mini 仍接收反馈；两者都不可见时，不为边界提醒唤起窗口或发系统通知。

## 切歌边界

先尝试现有分P切换，再由现有队列逻辑判定是否能够切歌。手动操作失败时：

| 情况 | 文案 |
| --- | --- |
| 无当前歌曲 | 暂无可播放的歌曲 |
| 顺序播放到第一首 | 已经是第一首了 |
| 顺序播放到最后一首 | 已经是最后一首了 |
| 随机模式没有历史 | 暂无上一首播放记录 |
| 随机候选耗尽 | 本轮随机播放已结束 |

不能只用列表下标判定边界，必须尊重历史记录、分P及循环模式。切歌按钮保持可触发，让空队列和边界操作获得解释；需要歌曲的播放/收藏控件保持原有禁用规则。自动结束、自动失败跳过沿用业务状态与错误提示，不发手动边界提醒。

## 贡献者验收

- 验证主窗口、沉浸页、mini、快捷键调用同一逻辑。
- 覆盖空队列、单首、首尾、随机历史及候选耗尽、列表循环、单曲循环、分P。
- 连续操作不堆叠；重要错误不被覆盖；成功切歌不会残留边界提示。
- mini 开关、消息到期和清除保持同步，提示不遮挡操作按钮。
- 新模块优先使用现有入口；局部校验和加载态留在所属区域。新增提醒类型或跨窗口协议时同步更新本文件。

本次仅接入切歌边界和现有播放提示，其他模块按需逐步接入。

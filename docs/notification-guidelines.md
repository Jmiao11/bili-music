# 用户操作反馈规范

所有贡献者在新增或修改用户可见的提示、加载态、错误态、确认交互或跨窗口反馈前，必须先阅读本规范。它是本项目用户操作反馈的唯一行为约定；提醒只解释操作结果，不能改变播放队列、循环、随机、分P、取流或其他业务状态。

当前已落地的是播放器的轻提示和播放失败提示。其他模块按本规范逐步接入，不能为了单个需求各自创建一套 Toast、系统通知或浮层。

## 类型选择

| 类型 | 使用场景 | 展示方式 |
| --- | --- | --- |
| 轻提示 | 队列边界、空队列、重复操作 | 2 秒后消失，不抢焦点 |
| 成功反馈 | 主动操作完成且界面变化不足以说明结果 | 简短轻提示；播放/暂停不重复提示 |
| 处理中 | 搜索、解析、导入等异步操作 | 操作区域加载态，结束后移除 |
| 警告或可恢复错误 | 失败、部分成功 | 相关区域展示原因及重试等下一步；需要处理时持续显示 |
| 阻断错误 | 功能无法继续 | 错误状态页或浮层，提供恢复入口 |
| 确认 | 删除等需要用户决策的操作 | 执行前使用项目自定义确认浮层 |

禁止将普通结果做成确认框，禁止使用浏览器 alert/confirm/prompt。错误码和堆栈留在日志中；面向用户说明发生了什么，必要时说明如何继续。

## 选择与归属

新增反馈前按下列顺序判断，优先使用离操作最近的既有组件：

1. 需要用户决定是否继续（例如删除）时，使用项目自定义确认浮层。
2. 操作正在进行、结果只影响当前页面或有明确重试入口时，使用所属页面的加载态、空状态或错误区；搜索、导入、收藏和歌单等模块不得借用播放器提示。
3. 操作会阻断当前流程时，使用错误状态页或浮层，并提供恢复、重试或返回入口。
4. 只有播放器域中由用户主动触发、但界面变化不足以解释结果的短暂结果，才能使用现有播放轻提示。

非播放器模块不得直接调用 `showPlaybackNotice()`，也不得复制其 DOM、样式或计时逻辑。确有跨页面、跨窗口的通用反馈需求时，先提出设计并同步更新本文件、统一入口和测试，再接入业务模块。未经单独设计和用户明确选择，不使用操作系统通知，也不因普通提醒唤起、抢焦点或恢复隐藏窗口。

## 当前统一入口

播放器域的唯一入口是 `ui/main.js` 中的 `showPlaybackNotice()`，复用已有 `#playback-notice`，不新建第二套 toast。边界和普通成功反馈**必须**显式传入 `showPlaybackNotice(message, { kind: "info" })`；该函数默认 `kind: "error"`，不得依赖默认值发送普通提示。

播放失败调用使用 `kind: "error"`；短暂错误显示 3200 毫秒，只有会阻止继续播放、且等待当前播放流程恢复的错误才使用 `persistent: true`。持久错误必须由对应的成功恢复、显式重试或播放流程终止调用 `clearPlaybackNotice()` 清除。`clearPlaybackNotice()` 只清除通知内容和定时器并同步窗口，绝不重置业务状态。当前 API 仅支持 info/error，其他类型使用上表规定的区域组件，不杜撰新 kind。

同时只显示一条消息，相同轻提示重复触发时刷新期限而不排队；新的错误可替换旧错误，以反映当前失败。错误显示期间忽略轻提示；轻提示不得覆盖错误，也不得写入或清除业务状态条。普通消息使用 `role="status"`、`aria-live="polite"`，不抢焦点、不播放提示音，允许读屏软件礼貌播报，且不只靠颜色传达含义。

主窗口在现有播放提示位置显示，沉浸页复用现有顶部位置。`bilibili-music-notice-change` 通知 mini host 发布状态，`mini-player-state.notice` 将内容同步到 mini 标题区域的紧凑提示，保留控制按钮可操作。计时和优先级仅由主窗口管理，mini 不重复计时；新打开的 mini 接收仍有效的消息，已过期的消息不回放。

全局快捷键、系统媒体控制、沉浸页、mini 均复用主窗口切歌入口。主窗口隐藏时 mini 仍接收反馈；两者都不可见时，不为边界提醒唤起窗口、抢焦点或发系统通知。

mini 使用单行摘要和「全文」按钮。展开后全文仅占用上方标题区域（最多 40px），不遮挡播放及还原按钮；可滚动、选中复制，支持 Tab 聚焦和 Escape 收起。全文区域及子元素必须排除原生窗口拖动。相同消息更新不重建文本，避免打断选区；新消息同步全文，清除时摘要、按钮和全文一并隐藏。只有焦点原本位于即将隐藏的提醒控件时才移回还原按钮。

## 切歌边界

先尝试现有分P切换，再由现有队列逻辑判定是否能够切歌。手动操作失败时：

| 情况 | 文案 |
| --- | --- |
| 无当前歌曲 | 暂无可播放的歌曲 |
| 顺序播放到第一首 | 已经是第一首了 |
| 顺序播放到最后一首 | 已经是最后一首了 |
| 随机模式没有历史 | 暂无上一首播放记录 |
| 随机候选耗尽 | 本轮随机播放已结束 |

不能只用列表下标判定边界，必须尊重历史记录、分P及循环模式。切歌按钮保持可触发，让空队列和边界操作获得解释；需要歌曲的播放/收藏控件保持原有禁用规则。自动结束、自动失败跳过沿用业务状态与错误提示，不发手动边界提醒。

边界操作不能清除待恢复播放的状态，否则应用重启恢复队列后，误按上一首/下一首会导致播放按钮无法继续恢复。成功手动切换分P应清除旧提示，与成功切换队列歌曲保持一致。

## 变更要求

以下任一变更都必须同步更新本文件，并补充或更新自动化测试：新增反馈类型、修改文案或持续时间、修改优先级或清除时机、增加新的展示位置、改变焦点/无障碍行为、改变 mini 或其他窗口间的事件与状态协议。

播放器通知改动至少覆盖 `tests/playback-notice.test.cjs`；涉及 mini 同步时同时覆盖 `tests/mini-player-window.test.cjs`。测试至少验证优先级、重复触发的计时刷新、显式清除、跨窗口同步和提示到期。涉及用户操作结果时，还应覆盖成功路径不会遗留旧提示。

## 贡献者验收

- 验证主窗口、沉浸页、mini、快捷键调用同一逻辑。
- 覆盖空队列、单首、首尾、随机历史及候选耗尽、列表循环、单曲循环、分P。
- 连续操作不堆叠；重要错误不被覆盖；成功切歌不会残留边界提示。
- mini 开关、消息到期和清除保持同步，提示不遮挡操作按钮。
- 新模块优先使用所属区域的既有组件；除播放器域外不得调用 `showPlaybackNotice()`。
- 检查提醒不改变业务状态、不抢焦点、不播放提示音；读屏文本可被 `aria-live="polite"` 礼貌播报。
- 新增提醒类型、调整通知语义或跨窗口协议时同步更新本文件和对应测试。

本次仅接入切歌边界和现有播放提示，其他模块按需逐步接入。
